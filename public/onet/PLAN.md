# แผนงาน: เว็บฝึกทำข้อสอบเข้า ม.1

ข้อสอบ 5 วิชา: คณิตศาสตร์ วิทยาศาสตร์ ภาษาอังกฤษ ภาษาไทย สังคมศึกษา
คลังข้อสอบวิชาละ **100 ข้อ** จัดเป็น **ชุดข้อสอบตายตัว ชุดละ 40 ข้อ** (3 ชุดต่อวิชา) ระดับความยากตั้งแต่ง่ายถึงยากระดับสอบเข้าห้องเรียน EP
เนื้อหาอิงหลักสูตรแกนกลาง พ.ศ. 2551 (ฉบับปรับปรุง 2560) ช่วงชั้น ป.4–ป.6 เน้น ป.6

## 1. สิ่งที่ได้จากการศึกษาโปรเจกต์ grammar และ tutor

| | `public/grammar` | `public/tutor` | `public/onet` (ใหม่) |
|---|---|---|---|
| หน่วยที่ทำ | เรื่องเดียว | เรื่องเดียว (ทำครบทุกข้อ) | **ชุดข้อสอบของทั้งวิชา** ข้ามหลายเรื่อง |
| การเลือกข้อ | สุ่ม 20 ข้อจากคลัง | ไม่สุ่ม | **ชุดตายตัว** ชุดละ 40 ข้อ ตามผังข้อสอบ (เรื่อง × ระดับ) |
| ระดับความยาก | ไม่มี | ไม่มี | `level` 1 ง่าย / 2 ปานกลาง / 3 ยาก |
| ผลสอบ | คะแนนรวม | คะแนนรวม | คะแนนรวม + **แยกตามเรื่องและระดับ** |

สิ่งที่นำมาใช้ต่อได้ทันที (ทั้งสองแอปเขียนแบบเดียวกัน คือ HTML + CSS + JavaScript ล้วน ไม่มี build step)

- โครงหน้า `index.html` / `app.js` / `style.css` ใช้ร่วมกันทุกวิชา ข้อมูลแยกเป็นไฟล์ JSON
- Hash routing (`#/`, `#/<วิชา>`, …) + `fetchJSON` + ตรวจรูปแบบไฟล์แล้วแจ้งว่าผิดข้อไหน
- `shuffle`, `shuffleOptions` (สลับตัวเลือกทุกครั้ง ยกเว้น `keepOrder`), ระบบตรวจทีละข้อ, ทบทวนข้อที่ผิด
- `rich()` ไฮไลต์ `**คำ**` และเก็บคะแนนใน `localStorage`
- ตัวอักษรตัวเลือก ก ข ค ง (ภาษาอังกฤษใช้ A B C D)
- สคริปต์ตรวจไฟล์แบบ `firebase-project/grammar/tools/validate.py` (เก็บไว้นอก `public` จะได้ไม่ถูก deploy)

## 2. ระดับความยากและสัดส่วน

| ระดับ | ความหมาย | ในคลัง (100) | ต่อชุด (40) |
|---|---|---|---|
| 1 ง่าย | จำ/เข้าใจ ขั้นตอนเดียว เนื้อหา ป.4–ป.5 | 25 | 10 |
| 2 ปานกลาง | นำไปใช้ 2–3 ขั้นตอน ระดับ O-NET ป.6 | 50 | 20 |
| 3 ยาก (EP) | วิเคราะห์/ประยุกต์ หลายขั้นตอน โจทย์บูรณาการ **ระดับสอบเข้าห้องเรียนพิเศษ EP** | 25 | 10 |

ข้อระดับ 3 ต้องยากกว่าข้อสอบแข่งขันทั่วไปอย่างน้อยหนึ่งขั้น เช่น
- คณิต/วิทย์: ต้องคิด 3 ขั้นขึ้นไป หรือเชื่อมสองเรื่องเข้าด้วยกัน (เช่น มุม + อัตราส่วน, วงจรไฟฟ้า + การอ่านผลการทดลอง)
- ภาษาอังกฤษ: คำศัพท์และโครงสร้างระดับ ม.1–ม.2 บทอ่านยาวขึ้น ถามการอนุมาน ไม่ใช่หาคำตอบที่เขียนไว้ตรง ๆ
- ภาษาไทย/สังคม: วิเคราะห์สถานการณ์ เปรียบเทียบหลักการ ตัวลวงถูกบางส่วนแต่ไม่ครบ

- ทุกช่อง (เรื่อง × ระดับ) ในคลังมีข้อสอบ **อย่างน้อย 2 เท่า** ของจำนวนต่อชุด จึงจัดได้ 3 ชุดที่รวมกันครอบคลุมทุกข้อในคลัง
- ข้อในชุด **เรียงจากง่ายไปยาก** (ข้อ 1–10 ง่าย, 11–30 ปานกลาง, 31–40 ยาก) ภายในระดับเดียวกันเรียงตามลำดับเรื่อง

## 4. โครงสร้างไฟล์และรูปแบบข้อมูล

```
public/onet/
  index.html, app.js, style.css, README.md
  data/subjects.json             ← รายชื่อวิชา เรื่อง ผังข้อสอบ และจำนวนชุด
  data/<วิชา>/<เรื่อง>.json       ← ข้อสอบของแต่ละเรื่อง (10–15 ข้อ)
  data/<วิชา>/sets.json           ← ชุดข้อสอบ: ข้อ ลำดับข้อ และลำดับตัวเลือกของแต่ละชุด
firebase-project/onet/tools/validate.py     ← สคริปต์ตรวจไฟล์ (นอก public ไม่ถูก deploy)
firebase-project/onet/tools/build_sets.py   ← สคริปต์สร้างชุดข้อสอบจากคลัง
```

แยกไฟล์ตามเรื่องเหมือน tutor เขียนและตรวจทานทีละเรื่องได้ง่าย ตอนเปิดวิชาโหลดทุกเรื่องและ sets.json พร้อมกัน

**`data/subjects.json`** (`draw` คือจำนวนข้อต่อชุด `[ง่าย, ปานกลาง, ยาก]` และ `sets` คือจำนวนชุดที่สร้างแล้ว)

```json
      "icon": "➗", "color": "#3056c8", "minutes": 60, "sets": 3,
      "topics": [
        { "id": "numbers", "title": "จำนวนและการดำเนินการ", "bank": [4, 8, 3], "draw": [2, 3, 1] }
      ]
    }
  ]
}
```

**`data/math/numbers.json`**

```json
[
  {
    "id": "math-numbers-01",
    "level": 1,
    "q": "คำถาม",
    "options": ["ก", "ข", "ค", "ง"],
    "answer": 0,
    "explanation": "วิธีคิด และเหตุผลที่ตัวลวงผิด"
  }
]
```

- `id` ไม่ซ้ำทั้งระบบ `sets.json` อ้างถึงข้อด้วย `id` จึงห้ามเปลี่ยนหลังสร้างชุดแล้ว
- `level` 1/2/3 บังคับทุกข้อ `explanation` บังคับทุกข้อ (tutor ไม่บังคับ)
- `image` (ไม่บังคับ) ชี้ไปไฟล์ SVG ใน `data/img/` สำหรับข้อเรขาคณิต กราฟ แผนภูมิ ควรมีไม่เกินประมาณ 10% ของคลัง พื้นหลังสีขาว ตั้งชื่อไฟล์ตาม `id` ของข้อ
- `bank` ใน `subjects.json` คือจำนวนข้อที่วางแผนไว้ในคลัง `[ง่าย, ปานกลาง, ยาก]` ใช้ให้ validate.py รายงานว่าเขียนครบหรือยัง
- ใช้กติกาเดิม: `answer` เริ่มนับจาก 0, `keepOrder`, ห้ามใช้ `"` ในข้อความ ให้ใช้ “ ”

**วิธีจัดชุดข้อสอบ** (`python tools/build_sets.py <วิชา>` เมื่อเขียนข้อสอบครบทุกเรื่องแล้ว)

```
จำนวนชุด = จำนวนข้อในคลัง ÷ 40 ปัดขึ้น (คลัง 100 ข้อ → 3 ชุด)
ทุกชุด: แต่ละเรื่องได้จำนวนข้อตาม draw และรวมได้ ง่าย 10 / ปานกลาง 20 / ยาก 10
แจกข้อของแต่ละช่อง (เรื่อง × ระดับ) วนไปทีละชุด → ทุกข้อได้ออกก่อนจึงเริ่มซ้ำ (3 ชุด = 120 ช่อง จึงซ้ำ 20 ข้อ)
เรียงข้อ ง่าย → ยาก (ระดับเดียวกันเรียงตามเรื่อง)
กำหนดลำดับตัวเลือกตายตัว ให้คำตอบที่ถูกกระจายเป็น ก ข ค ง ใกล้เคียงกัน (10-10-10-10)
```

ชุดข้อสอบเหมือนกระดาษข้อสอบจริง ทำซ้ำได้ชุดเดิมทุกครั้ง คะแนนเทียบกันได้ระหว่างรอบ และคุยกันได้ว่า “ชุดที่ 2 ข้อ 15 ตอบ ค”
สคริปต์ไม่สร้างทับ sets.json ที่มีอยู่แล้ว (ต้องใส่ `--force`) เพราะคะแนนของผู้เรียนผูกกับเลขชุด

**สิ่งที่ validate.py ตรวจ**: JSON ถูกต้อง, ข้อละ 4 ตัวเลือกไม่ซ้ำกัน, `answer` อยู่ในช่วง, `id` ไม่ซ้ำ, ทุกข้อมี `level` และ `explanation`, จำนวนข้อแต่ละเรื่อง × ระดับ ≥ `draw` (เตือนถ้าน้อยกว่า 2 เท่า), รวม `draw` ทั้งวิชา = 40, คำถามซ้ำกัน, `**` ไม่ครบคู่ และทุกชุดใน sets.json: 40 ข้อไม่ซ้ำในชุด จำนวนข้อต่อเรื่องและต่อระดับตรงผัง ลำดับตัวเลือกถูกต้อง ข้อในคลังที่ไม่อยู่ในชุดใดเลย

## 6. แนวทางเขียนข้อสอบ

- ตัวลวงทุกตัวมาจากความเข้าใจผิดที่พบบ่อย ไม่ใช่ตัวเลือกที่ตัดทิ้งได้ทันที
- ข้อยากต้องยากเพราะต้องคิดหลายขั้นหรือเชื่อมหลายเรื่อง ไม่ใช่เพราะคำถามกำกวมหรือหลอก

- หลีกเลี่ยง “ถูกทุกข้อ / ผิดทุกข้อ” ถ้าจำเป็นต้องใส่ `keepOrder`
- ตรวจข้อเท็จจริงที่เปลี่ยนตามเวลาก่อนใช้ เช่น จำนวนประเทศสมาชิกอาเซียน รัฐธรรมนูญฉบับปัจจุบัน
- คณิตศาสตร์: ทุกข้อแก้โจทย์ซ้ำอีกรอบเพื่อยืนยันคำตอบก่อนบันทึก
